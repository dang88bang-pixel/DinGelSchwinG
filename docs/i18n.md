# i18n (Internationalisierung) — Gerüst & Rollout

Die App war bisher fest verdrahtet deutsch. Mit diesem Stand steht das
**i18next/react-i18next-Gerüst** inklusive Live-Umschalter:

| Datei | Inhalt |
|---|---|
| `src/i18n/index.ts` | Initialisierung (`lng: de`, `fallbackLng: de`) |
| `src/i18n/locales/de.json` / `en.json` | Ressourcen (App-Shell + `common.*`-Pool) |
| `src/components/AppChrome.tsx` | Sprachumschalter DE/EN (unten rechts) + Offline-Badge |
| `src/App.tsx` | importiert `./i18n` (Initialisierung beim App-Start) |

Strings liegen gebündelt als JSON im Source (kein Netz-Nachladen —
wichtig für das Android-WebView/APK).

## Verwendung in Komponenten

```tsx
import { useTranslation } from 'react-i18next';

function SomePanel() {
  const { t } = useTranslation();
  return <button>{t('common.save')}</button>;   // „Speichern“ / "Save"
}
```

Mit Platzhaltern: `t('audit.count', { n: 5 })` + JSON-Key
`"count": "{{n}} Einträge"` / `"count": "{{n}} entries"`.

## Rollout-Plan (restliche Komponenten)

Priorisierung nach Sichtbarkeit; pro Schritt Lint+Build grün halten
(`npm run lint && npm run build`):

1. **NetworkDashboard** (Hauptansicht, Header/Tabs)
2. **AgentConsole** + **MoEChatInterface** (Chat-UX)
3. **PairingPanel / MeshControl / NetworkSettings** (Formular-Strings)
4. **diagnostics/** + **ReplayEditor / RosettaPanel** (Spezial-UI)

Konventionen:

- Schlüssel flach im Namespace `bereich.element`, z. B. `chat.send`,
  `devices.bind`. Keine deutschen Sätze als Schlüssel.
- Gemeinsames Vokabular (save/cancel/…) **nur** unter `common.*`.
- Datum/Zahlen NICHT in Strings einbauen — `Intl.DateTimeFormat` mit
  `i18n.language` verwenden.
- Android: Kein separater Schritt nötig — Ressourcen landen über den
  Vite-Build automatisch im APK (`cap sync`).

## Tests

```bash
npm run lint && npm run type-check && npm run build
```

Sprache wechseln → Chips unten rechts; die Wahl wird in `localStorage`
(`dingelschwing.lang`) persistiert und beim nächsten Start wiederhergestellt
(`src/i18n/index.ts`).

## Stand: portierte LobeChat-Features

Rollen-, Panel- und Gateway-Texte sind in `src/i18n/locales/{de,en}.json` unter
`app.*`, `common.*`, `panels.{gallery,dashboard,knowledge,mcp}.*`, `gateway.*`, `strip.*`.
`LiveStatusStrip`, `NetworkDashboard` (Header/Buttons) und die Panel-Titel laufen darüber;
die Antwort-**Texte des Agenten** bleiben bewusst deutsch, weil sie Determinismus-Spiegel der
Python-Engine sind (`desktop/utils/agent.py`) – eine Übersetzung der Engine-Ausgaben würde die
1:1-Parität Web/Desktop brechen.

Neue Schlüssel, die mit dem BLE-Gateway dazukamen: `panels.dashboard.agentProof`,
`proofPsk`, `proofForced`, `proofOptional`, `proofBad`, `proofSuspended`, `agentProofHint`
(Interpolation `{{fp}}` für den PSK-Fingerabdruck).

Fehlertoleranz: `i18n` hat `fallbackLng: 'de'`; unbekannte Schlüssel liefern den Schlüsselnamen
statt einer Leerstelle, damit fehlende Übersetzungen in der UI auffallen.
