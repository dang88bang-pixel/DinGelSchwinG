## Befund 2 (gefunden von der CI, behoben): USB-Tests hängen vom Host-`usb.ids` ab

Der erste CI-Lauf des neuen Workflows war rot. Ursache war **nicht** das Audit, sondern ein
Test-Befund, den der Harness nur in einer Umgebung mit installierter System-`usb.ids` zeigen kann:

```
❌ test_usb_vendor_parsers_and_lookup: AssertionError: {… 'name': 'Metrologic Instruments',
   'via': '/usr/share/hwdata/usb.ids' …}     (erwartet: „Honeywell …")
❌ test_usb_store_prefers_host_sources: AssertionError: {… 'name': 'Fairphone B.V.',
   'also_in': '/tmp/dgs-usb-hostsources-…/adb_usb.ini' …}
```

**Ursache:** `vendors.load()` liest zusätzlich die System-Quellen
(`/usr/share/hwdata/usb.ids`, udev-Regeln, `adb_usb.ini`) und lässt sie laut Dokumentation
(`docs/usb-hersteller.md`) **bewusst** gegen die built-in-Kurzliste gewinnen. Auf dem
GitHub-Runner — wie auf jedem üblichen Linux-Desktop — ist `usb.ids` installiert und ordnet
`0c2e` „Metrologic Instruments" statt „Honeywell" zu. Die Tests waren damit host-abhängig;
lokal (Sandbox ohne `hwdata`) waren sie grün. **Kein Produktfehler.**

**Behoben (nur Testdatei, Backup nach `backups/phase3/`):** neuer Helfer
`_without_host_usb_sources()` legt für die beiden Tests die Systempfade kurz still
(inkl. `_CACHE`, mit `finally`-Wiederherstellung). Verifiziert mit einer emulierten
CI-Umgebung (`USB_IDS_CANDIDATES → /tmp/fake-hw/usb.ids`): vorher **45/47**, jetzt
**47/47** — mit und ohne System-`usb.ids`, dreimal wiederholt stabil.

## Befund 1: Test läuft nur ohne lokales Gateway (Umgebungsabhängigkeit)

`npm test` ist grün (20/20) — **aber nur, solange kein Gateway auf 8791 lauscht.**
Mit laufendem `npm run mcp:gateway` (Mock-Modus) schlägt genau ein Test fehl:

```
FAIL src/lib/agent/__tests__/agentEngine.test.ts
  > intentScanLive scheitert ohne Gateway strukturiert (kein Fake-Erfolg)
  AssertionError: expected '✅ Netzwerk-Scan für 192.168.1.0/24 ab…' to include '0 Fund'
```

**Ursache:** `intentScanLive` → `runLiveScan` fragt PortView **und** das Gateway
(`gatewayCommand('ble_scan')`) live ab. Mit laufendem Gateway liefert der Mock-Scan
Geräte, der Text enthält dann nicht mehr „0 Fund" — der Test ist auf den Offline-Fall
geschrieben (Name: „scheitert ohne Gateway").

**Bewertung:** kein Produktfehler, sondern fehlende Test-Isolation (der Test mockt die
Live-Quellen nicht weg). **Workaround:** Gateway vor `npm test` stoppen.
**Empfohlener Fix (separater Auftrag):** im Test den Gateway-/PortView-Zugriff stubben
(z. B. `vi.mock('../../endpoint')`) oder einen Offline-Schalter im Engine-Pfad nutzen.
In der CI tritt das nicht auf (keine Dienste gestartet) — `reports/harness.json` bleibt dort grün.
